# Project Instructions

## Development
- Inspect existing code before modifying it.
- Follow established architecture and conventions.
- Prefer small, maintainable changes.
- Add tests for new functionality.
- Never commit credentials or secrets.

## Workflow
- Use OpenSpec for significant changes.
- Review relevant specifications before implementation.
- Use `docs/notes/` for observations, questions, and research. Promote agreed,
  testable behavior into OpenSpec; do not treat notes as requirements.
- Read `docs/notes/README.md` for the notes-to-spec workflow.
- Explain major architectural decisions.
- Run applicable tests before committing.

## Git
- Work on feature branches.
- Use descriptive commit messages.
- Do not push or merge without approval.
